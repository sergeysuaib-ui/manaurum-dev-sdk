# Completeness skeptic: areas the 7 audit dimensions probably did not cover

Inputs: only `SDK-TOC.md` (origin/main 6f52dce) and `manifest_v2.schema.json`. I did not open the SDK, the platform source, or any other findings.
Method: I walked the developer journey and, for each schema property, looked for a TOC heading that plausibly covers it. Wherever the owning dimension (1 to 7) is unclear, or no TOC section exists, the item is listed here.
Risk levels: **H** = a developer ships something broken or unsafe and no linter catches it. **M** = wasted cycles or a confusing failure. **L** = cosmetic, or rarely hit.

Ranked:

| # | Area / schema property | TOC evidence | Question the auditor should ask | Risk |

Dimension 7's "agent ergonomics" means Claude Code, not the OS Assistant, so no dimension owns this area. | Does the SDK say that **omitting `is_write` means write**, which triggers user approval on every read-only tool? ## Cross-cutting note
The schema marks **`schedules` and `webhooks` as DEFERRED** and declares **`offline`**, yet the TOC has no heading for any of them. The README "Honest gaps" section (line 195) is the obvious place for these. An auditor should check whether it lists schedules, webhooks, offline, and the logs stub, and whether the stub is described as deferred or as working.
